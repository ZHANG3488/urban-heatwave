# Urban heatwave response analysis

Python scripts for the urban-rural heatwave diurnal-response study. The release
contains the original metrics, Figure 3 and Figure 4 analysis implementations,
five plotting scripts, and the author-supplied frozen Figure 2 group summary.
Numerical algorithms, thresholds, random seeds, resampling counts and cohort
definitions are retained. Personal paths and script-history labels are removed.

## Installation

Use Python 3.12 (the release-check interpreter). From the repository root:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Alternatively, use `conda env create -f environment.yml` and activate
`urban-heatwave-response`. Dependencies are pinned to the tested release environment; this is not the frozen
original research environment. `requirements-tested-lock.txt` records all installed
packages for the checks. See RELEASE_VERIFICATION.json for checks performed.

## Inputs

Input observations are not included. Supply these paths or override them using
the scripts' command-line arguments:

| Path | Content |
| --- | --- |
| `data/station_pairs.csv` | Original urban-rural station-pair metadata |
| `data/station_metadata.csv` | Original auxiliary station metadata |
| `data/isd_lite/` | Original ISD-Lite observation files |
| `data/era5_station_daily/` | Original station daily ERA5 Tmax extracts |
| `data/continents/World_Continents.shp` | Continent polygons, with companion files |
| `data/koppen_geiger/koppen_geiger_0p00833333.tif` | Original climate classification raster |
| `data/stations_building_volume_100m.csv` | Original building-volume table |

Keep original station identifiers, units and column names when running analyses.
Removing personal machine paths does not anonymize observations, and no scientific
input values have been perturbed. Data access instructions and the original data
preparation steps must accompany a complete raw-data reproduction release.

## Workflow

Run the following commands from the repository root. Analysis output directories
should be new; some original scripts reject existing directories, whereas the
Figure 4 prediction analysis can overwrite its own output files.

### Pair metrics and Figures 1-2

```bash
python 01_compute_pair_period_metrics.py
python 02_plot_figure1_global_daynight.py
python 03_plot_figure2_two_component_state.py
```

Figure 2 reads `source_data/Supplement_pair_level_HW_NHW_distribution_summary.csv`.
This is the original group summary, copied without any numerical change. Its
generator was not supplied: Figure 2 can be replotted from this frozen table,
but the summary confidence intervals cannot be independently regenerated from
the supplied code alone. See source_data/README.md.

### Figure 3

```bash
python analyze_figure3_timing.py
python analyze_figure3_state.py
python analyze_figure3_dynamics.py
python 04_plot_figure3_response_channels.py
```

Timing and state analyses read the pair metrics. Dynamics reads their verified
bundles, daily heatwave flags, station-year availability and ISD-Lite observations.
The plot reads `outputs/analysis/figure3_dynamic_mechanism/`.
Bundle producer and consumer labels have been renamed together; use bundles
generated by this release. Do not relabel an old bundle or bypass its integrity
checks to make it load. Keep all original seeds and resampling settings for
formal analysis; `--test-mode` is only for development checks.

### Figure 4

```bash
python analyze_figure4_response_states.py --final-analysis
python analyze_figure4_prediction.py --final-analysis
python 05_plot_figure4_predictive_state.py
```

The first analysis imports the renamed metrics script and writes early/late
response states to `outputs/analysis/figure4_response_states/tables/`. The second
reads those states and creates final figure source tables in
`outputs/analysis/figure4_predictive_state/tables/`.
An optional original reference run can be supplied with `--reference-run-dir`;
without it the original optional historical-run comparison is not performed.

The two analysis scripts intentionally retain distinct performance summaries.
For Figure 4 use the final `figure4a_joint_performance_source.csv` emitted by
`analyze_figure4_prediction.py`, not the base analysis performance table. Its
joint Q2 uses unstandardized Rx/Rn errors pooled over both outcomes, with the
outcome-wise observed means as denominator baselines, after averaging repeated
out-of-fold predictions. It is not the mean of per-repeat Q2 values.

### Supplementary state illustration

```bash
python 06_plot_supplementary_mean_amplitude_states.py
```

### Development checks

```bash
python analyze_figure4_response_states.py --self-test
python analyze_figure4_prediction.py --self-test
python 02_plot_figure1_global_daynight.py --self-test
python 03_plot_figure2_two_component_state.py --self-test
python 05_plot_figure4_predictive_state.py --self-test
python 06_plot_supplementary_mean_amplitude_states.py --self-test
```

Synthetic checks do not validate manuscript estimates against the original
observations. Formal resampling settings and seeds remain those of the original
scripts, including their differences between analyses.

## Release scope and privacy

Only the explicitly included group-level Figure 2 CSV is distributed. Other
data and generated products are excluded by `.gitignore`. Generated manifests
may contain absolute local paths: do not force-add them without inspection.
QC method identifiers and software-version reporting are retained because they
describe scientific provenance rather than personal revision history.

No software reuse license has been selected by the authors. Uploading this
repository is distinct from licensing it for redistribution or reuse.
